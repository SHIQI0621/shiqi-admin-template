## 目标
把 `src/views/feature/` 下 18 个演示页统一为规范的文档结构,并消除重复样式。

## 统一页面结构(每页按需采用)
每页拆成独立 `el-card` 板块,沿用 baseTag 标准模板的命名:
1. **介绍卡** `intro-card` — 组件名 + 一段简介 + (可选)依赖/独立使用说明
2. **效果预览卡** `preview-card` — 实时可交互预览,可分组(`section-title`)
3. **基础用法卡** `usage-card` — 代码写法,统一 `code-block`(HTML 转义 + Fira Code + 灰底圆角)
4. **属性说明卡** `props-card` — `el-table`,列:`属性/类型/默认值/说明`
5. **事件说明卡** `events-card` — `el-table`,列:`事件名/参数/说明`(无事件则不渲染)
6. **插槽说明卡** `slots-card` — `el-table`,列:`插槽名/说明`(无插槽则不渲染)
7. **实际应用预览卡** `app-preview-card` — 真实业务场景演示

> hook/directive 类页面(`copyText`/`network`/`watermark`/`rippleEffect`):「属性说明」改为「参数说明」,「事件说明」改为「返回值/回调说明」。
> store 驱动无对外 API 的组件(`FullScreenToggle`/`LanguageSelector`/`LockScreen` 等):在介绍卡注明"无对外 API,行为由内部 store 控制"。

## 第 0 步:抽取公共样式文件(用户已确认方案)
- 新建 `src/views/feature/styles/demo.scss`,集中定义文档页骨架样式:`.intro-card/.preview-card/.usage-card/.props-card/.events-card/.slots-card/.app-preview-card` 卡片间距,`.intro-section/.intro-title/.intro-text/.intro-tips/.intro-usage`,`.card-header/.header-title`,`.section-title/.preview-section`,`.usage-section/.usage-subtitle`,`.code-block`,`.app-examples/.example-title/.example-row`,以及 API 表格统一表头底色约定。颜色统一用 Element Plus CSS 变量(`var(--el-fill-color-lighter)` 等)。
- 在 `src/styles/index.scss` 顶部 `@use` 引入一次(全局可用),消除 18 页重复定义;各页面删除与该文件重叠的 scoped 样式。
- 代码块统一为:`<pre class="code-block"><code>…转义内容…</code></pre>`,Fira Code 字体、8px 圆角、`var(--el-fill-color-lighter)` 背景。

`avatarList`、`card`、`qrCode`、`iconButton`、`imageCropper`、`copyText`、`rippleEffect`、`imagePreview`

`icon` — 保持图标管理器工具页性质,不强套文档结构,仅统一配色变量、代码块风格、补一段「独立使用」介绍说明。

## 验证方式
- 每批完成后运行 `npx vue-tsc -b` 做类型检查,确保不引入新的类型错误(注:项目存量有 TS6133 未使用变量告警,属既有问题,重构中顺带清理涉及页面的此类告警)
- 全部完成后启动 `npm run dev` 抽查几个代表性页面(如 baseTag、qrCode、animatedNumber、network)能正常渲染与交互
- 严格依据调研到的真实 API 填表,不臆造属性/事件

## 注意事项
- API 表内容**严格依据**前序调研的真实 props/emits/slots(已逐字核对源码),如 RichParser 模板实际用未过滤的 `content`(非 sanitizeHtml),文档如实标注
- 保持各页现有业务逻辑与交互不变,只重构「文档结构 + 样式」,不改组件本身
- 保持现有各页根命名空间 class(如 `base-tag-page`),不破坏路由/菜单
